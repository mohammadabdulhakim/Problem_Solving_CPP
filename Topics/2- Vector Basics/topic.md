## 1️⃣ المشكلة: ليه الـ Static Array مزعج؟

أنت عارف المصفوفات العادية:

```cpp
int arr[5];
```

✅ مميزاتها:

* سريعة جدًا
* الوصول لأي عنصر فيها سطر واحد

❌ مشاكلها:

1. **الحجم ثابت**

   * لازم تحدده من الأول
   * لو احتجت عنصر زيادة → خلاص، ضاعت

2. **يا إما ضيق… يا إما واسع زيادة عن اللزوم**

   * تختار حجم صغير → يطلع مش كفاية
   * تختار حجم كبير → ذاكرة محجوزة على الفاضي

### تشبيه 👇

تخيل قاعة سينما فيها **100 كرسي**:

* لو جه 101 شخص → مفيش مكان
* لو جه 20 شخص → 80 كرسي فاضي ومهدورين

وده بالظبط اللي بيحصل مع الـ Static Array.

---

## 2️⃣ الحل السحري: Vector 🎩✨

هنا ييجي الحل الذكي:

```cpp
vector<int> v;
```

### يعني إيه Vector؟

الـ **Vector** هو:

> مصفوفة ذكية بتكبر وتصغر لوحدها حسب احتياجك.

```cpp
v.push_back(10);
v.push_back(20);
v.push_back(30);
```

❌ مفيش تحديد حجم من الأول
❌ مفيش قلق
✅ ضيف براحتك

### تشبيه 👇

الـ Vector زي **شنطة سفر مرنة**:

* تحط هدوم → تمام
* الشنطة مليت؟
  👉 تغيرها بشنطة أكبر وتنقل الحاجة

بس خلّي بالك… النقل ده **مش بيحصل كل مرة** 👀
وده يودينا لأهم جزء…

---

## 3️⃣ آلية العمل (Under the Hood) 🔧

**الجزء اللي بيخلّي الناس تتلخبط**

الـ Vector عنده مفهومين مهمين جدًا:

### 🟦 Size

عدد العناصر اللي جوه الـ Vector حاليًا

```cpp
v.size();
```

### 🟨 Capacity

المساحة المحجوزة فعلًا في الذاكرة

```cpp
v.capacity();
```

---

### 👀 السيناريو الحقيقي في الذاكرة

افرض عندنا:

```cpp
vector<int> v;
```

#### أول `push_back`:

* يحجز مساحة صغيرة (مثلاً 1)
* size = 1, capacity = 1

#### تاني `push_back`:

capacity خلصت 😱
فيعمل إيه؟

### اللي بيحصل بالظبط:

1️⃣ يحجز **مساحة أكبر** (غالبًا ضعف القديمة)
2️⃣ ينسخ كل العناصر القديمة
3️⃣ يضيف العنصر الجديد
4️⃣ يمسح المساحة القديمة

💥 العملية دي **مكلفة شوية**
بس مش بتحصل كل مرة 👇

---

### مثال رقمي:

| العملية | size | capacity |
| ------- | ---- | -------- |
| push 1  | 1    | 1        |
| push 2  | 2    | 2        |
| push 3  | 3    | 4        |
| push 4  | 4    | 4        |
| push 5  | 5    | 8        |

> إعادة الحجز بتحصل **نادراً**
> وده سبب فكرة مهمة جدًا 👇

---

## 4️⃣ الأداء (Performance) ⚡

### ✅ الوصول للعناصر (Random Access)

```cpp
v[3];
```

⏱️ **O(1)**
زي الـ array العادي بالظبط

ليش؟

> لأن العناصر متخزنة **متجاورة في الذاكرة**

---

### ✅ الإضافة في الآخر `push_back`

* في معظم الوقت: **O(1)**
* أحيانًا (وقت التوسعة): **O(n)**

لكن المتوسط =
✅ **Amortized O(1)**

### تشبيه 👇

زي إنك:

* تمشي كل يوم 1 كم
* مرة واحدة في الشهر تمشي 10 كم
  المتوسط العام؟
  لسه صغير ✅

---

## 🔑 ملحوظة احترافية

لو عارف العدد التقريبي من الأول:

```cpp
v.reserve(1000);
```

💡 كده بتقلل عدد مرات النسخ
💡 كود أسرع وأنضف

---

## ✅ مقارنة سريعة

|           | Array | Vector    |
| --------- | ----- | --------- |
| الحجم     | ثابت  | ديناميكي  |
| الوصول    | O(1)  | O(1)      |
| الإضافة   | ❌     | ✅         |
| المرونة   | قليلة | عالية     |
| الاستخدام | محدود | واسع جدًا |

---

## 🎯 الخلاصة كـ Coach

* الـ **Vector** = Array + ذكاء + مرونة
* بيخزن البيانات متجاورة
* بيكبر لما يحتاج
* سريع جدًا في الاستخدام الحقيقي
* أساس أي مبرمج C++ محترف

# 1️⃣ أهم **Vector Methods** اللي لازم تحفظها وتفهمها (مش بس تحفظها)

هنمشي من اللي بتستخدم يوميًا للي احترافي.

---

## 🔹 إنشاء Vector

```cpp
vector<int> v;
vector<int> v(5);        // size = 5
vector<int> v(5, 10);    // [10,10,10,10,10]
```

---

## 🔹 الإضافة والحذف

```cpp
v.push_back(7);     // إضافة في الآخر
v.pop_back();       // حذف آخر عنصر
```

⏱️ `push_back` → Amortized O(1)

---

## 🔹 الوصول والقراءة

```cpp
v[i];        // سريع جدًا O(1)
v.at(i);     // آمن (بيعمل check)
v.front();
v.back();
```

> ⚠️ `at()` أبطأ شوية لكنه أأمن (throws exception)

---

## 🔹 الحجم والذاكرة (مهم جدًا)

```cpp
v.size();      // عدد العناصر
v.capacity();  // المساحة المحجوزة
v.empty();     // هل فاضي؟
```

---

## 🔹 التحكم في الذاكرة (احترافي جدًا)

```cpp
v.reserve(1000);   // احجز مساحة من بدري
v.clear();         // يمسح العناصر (capacity تفضل)
v.shrink_to_fit(); // يقلل capacity (مش مضمون 100%)
```

---

## 🔹 التعديل

```cpp
v.insert(v.begin()+2, 100);
v.erase(v.begin()+2);
```

⛔ دول **O(n)** → استخدمهم بحذر في المسابقات

# 2️⃣ Vector vs List (فرق مهم جدًا)

خلّينا نعمل مقارنة مباشرة 👇

| المقارنة               | vector            | list         |
| ---------------------- | ----------------- | ------------ |
| التخزين                | متجاور في الذاكرة | Nodes متفرقة |
| الوصول `v[i]`          | ✅ O(1)            | ❌ O(n)       |
| insert/delete في النص  | ❌ O(n)            | ✅ O(1)       |
| cache friendly         | ✅ جدًا            | ❌            |
| الاستخدام في المسابقات | ⭐⭐⭐⭐⭐             | ⭐            |
| memory overhead        | قليل              | كبير         |

---

## 🧠 ليه الـ Vector أكسب دائمًا تقريبًا؟

* أسرع بسبب cache
* أسهل
* مباشر
* أغلب المسائل محتاجة Random Access

### متى أستخدم list؟

> تقريبًا **نادر جدًا**
> لو:

* عندك حذف/إضافة كتير جدًا في النص
* ومش محتاج وصول عشوائي

💡 في المسابقات؟
**99% Vector** ✅

---

## 3️⃣ أخطاء شائعة بتضيّع وقتك في المسابقات ⏳🔥

ده أخطر جزء 👇

---

### ❌ 1) نسيان `reserve()`

```cpp
vector<int> v;
for(int i=0;i<1e6;i++) v.push_back(i);
```

✅ الصح:

```cpp
v.reserve(1e6);
```

⏱️ فرق أداء **ضخم** في inputs الكبيرة

---

### ❌ 2) استخدام insert/erase جوه loop

```cpp
for(...) {
   v.erase(pos); // كارثة
}
```

⛔ O(n²)

✅ الحل:

* استخدم index
* أو two pointers
* أو array بدلها

---

### ❌ 3) مسح الـ vector بطريقة غلط

```cpp
v.clear();  // فاكر الذاكرة اتحررت ❌
```

✅ الحقيقة:

* size = 0
* capacity زي ما هي

✅ لو محتاج تمسح الذاكرة:

```cpp
vector<int>().swap(v);
```

---

### ❌ 4) Access out of bounds (SIGSEGV 💀)

```cpp
v[5] = 10; // size = 3
```

✅ استخدم:

```cpp
if(i < v.size())
```

---

### ❌ 5) استخدام list بدون سبب

```cpp
list<int> l; // ليه؟
```

⛔ أبطأ
⛔ memory أكتر
⛔ صعب تتعامل معاه

---

### ❌ 6) Passing vector by value

```cpp
void solve(vector<int> v) // نسخة 😱
```

✅ الصح:

```cpp
void solve(const vector<int>& v)
```

---

# 🏁 Coach Summary (احفظ دول ✅)

* vector = default choice
* random access سريع
* reserve = سلاحك السري
* list نادر جدًا
* erase/insert في النص = خطر
* pass by reference مهم
